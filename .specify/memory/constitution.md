# دستور المشروع (Project Constitution) — تطبيق مستندات Android محلي

تم اعتماد هذا الدستور كمرجع أساسي ملزم لجميع مراحل التطوير البرمجي واستخدام Spec Kit وأدوات الوكلاء الذكية.

---

## المبدأ الأول: الخصوصية المحلية الصارمة (Local Privacy by Design)
1. جميع عمليات المعالجة وقراءة وكتابة المستندات والصور تتم محلياً 100% داخل عتاد الجهاز.
2. لا اتصالات شبكية، لا خوادم وسيطة، لا مزامنة سحابية، لا تحليلات مرسلة (Analytics)، ولا تسجيل دخول أو حسابات.
3. يُمنع منعاً باتاً وجود إذن `android.permission.INTERNET` في Manifest الإنتاج النهائي.
4. جميع النماذج اللغوية (OCR Models) والمكتبات تكون مدمجة داخل التطبيق؛ لا يُسمح بتنزيل أي ملفات وقت التشغيل.

---

## المبدأ الثاني: سلامة المصدر وإدارة الملفات (Source File Integrity)
1. لا يُعدل الملف الأصلي في مكانه نهائياً. كل عملية معالجة أو تحرير تنتج ملفاً مستقلاً جديداً.
2. يتم حفظ الملف الجديد فقط في الوجهة التي يحددها المستخدم عبر منتقي الحفظ القياسي Storage Access Framework (SAF).
3. استخدام `Uri` كمعرّف أساسي للملفات، مع عدم افتراض مسارات ملفات تقليدية (`java.io.File`) لأن الملفات قد تكون على وحدات تخزين خارجية أو سحابية للمستخدم.
4. تنظيف كافة الملفات المؤقتة (`cacheDir`) بشكل فوري عند انتهاء العملية سواء بالنجاح أو الفشل أو الإلغاء، وتنظيفها عند بدء التطبيق بعد أي توقف غير متوقع.

---

## المبدأ الثالث: الصدق الوظيفي والشفافية (Functional Honesty)
1. عدم عرض أي ميزة غير مكتملة كأنها جاهزة؛ استخدام وسم «قريبًا» أو إخفاء الأداة حتى اكتمالها الفعلي.
2. توضيح حدود التقنيات المتقدمة (مثل OCR، استرداد الملفات التالفة، وضغط المستندات) للمستخدم بصدق:
   - الضغط يعرض الحجم الفعلي قبل وبعد، ولا يدعي خفض الحجم إن لم ينخفض فعلياً.
   - محرك الإصلاح يبين الاسترداد الجزئي أو الفشل بوضوح عبر `RepairReport`.
3. التحقق المسبق من تراخيص كافة التبعيات البرمجية وضمان توافقها (Apache 2.0 / MIT) واستبعاد التراخيص المقيدة (AGPL/GPL).

---

## المبدأ الرابع: المعمارية النظيفة والقابلة للتبديل (Clean & Modular Architecture)
1. الالتزام بـ Modern Android Development: Kotlin، Jetpack Compose، Material 3، Coroutines، StateFlow.
2. فصل صارم بين الطبقات:
   - **العرض (Presentation):** Compose UI و ViewModels بحالات غير قابلة للتغيير (`StateFlow<UiState>`). الشاشة والـ ViewModel لا يتعاملان مع SDK خارجي مباشرة.
   - **المجال (Domain):** UseCases وكيانات نقية مستقلة عن تفاصيل منصة Android.
   - **البيانات (Data):** المستودعات (Repositories)، ومحولات المحركات (Engine Adapters)، وقاعدة البيانات (Room)، والإعدادات (DataStore).
3. وضع كل محرك معالجة خلف واجهة برمجية مستقلة وقابلة للاستبدال أو الفحص الشكلي (Mocking):
   - `PdfDocumentEngine`
   - `PdfOptimizationEngine`
   - `PdfFormEngine`
   - `PdfRepairEngine`
   - `OcrEngine`
   - `ScannerEngine`

---

## المبدأ الخامس: تجربة مستخدم عربية أولاً (Arabic-First RTL UX)
1. التطبيق موجه بالعربية RTL افتراضياً، مع دعم كامل للإنجليزية LTR.
2. استخراج جميع النصوص دون استثناء في ملفات الموارد `strings.xml`.
3. اختبار التخطيط وتدفق الشاشات واتجاه المحاذاة بصرياً في الوضعين RTL و LTR.
4. توفير حالات تفاعلية كاملة لكل شاشة وعملية: التحميل، التقدم، النجاح، الفراغ (Empty State)، الخطأ، وإعادة المحاولة.

---

## المبدأ السادس: الأمان والموثوقية (Security & Reliability)
1. منع تنفيذ معالجة الملفات أو تصيير الصفحات أو عمليات التشفير على الـ Main Thread نهائياً؛ استخدام `Dispatchers.IO` و `Dispatchers.Default`.
2. حظر استخدام المعامل `!!` (Null Assertion) في كافة ملفات الكود لضمان انعدام انهيارات `NullPointerException`.
3. منع تسجيل محتوى المستندات أو نصوص OCR أو أسماء الملفات الحساسة في الـ Logcat أو ملفات السجل.
4. سجل العمليات (History) يحفظ فقط البيانات الوصفية (`Uri`, `displayName`, `sizeBytes`, `timestamp`) دون حفظ محتوى أو نسخة خفية من الملفات.
5. القفل الأمني للتطبيق يعتمد فقط على `BiometricPrompt` وبيانات اعتماد شاشة قفل الجهاز الرسمية دون تخزين PIN مخصص غير آمن.

---

## المبدأ السابع: التحقق والجودة المستمرة (Continuous Verification)
1. الحفاظ على استقرار المشروع وقابليته للبناء والاختبار في كل مرحلة.
2. إضافة اختبارات وحدة مناسبة لكل ميزة جديدة ومحرك ومنطق أعمال (Use Cases).
3. فحص الـ Manifest النهائي باستمرار للتأكد من خلوه من أذونات غير مصرح بها.
